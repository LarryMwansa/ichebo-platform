nested inside another is invalid HTML5, and browsers respond by flattening it — the nested form tag is dropped and its children become part of the OUTER form. That meant this.closest('form').requestSubmit() on the file input's onchange was submitting the WHOLE LESSON FORM (a normal POST to the lesson's own save URL, 302 redirect, full page navigation) instead of hitting the attachment upload endpoint — confirmed by watching the real network request in a browser: it went to /learn/author/lesson//, never to /learn/htmx/attachments//upload/. The document was never sent to the view that saves it; the page just navigated back to the authoring list. Fixed by putting hx-post directly on the file input — no form wrapper, so no nesting. htmx auto-includes a form-control element's own value when it is itself the hx-post trigger (the selected file, encoded as multipart because of hx-encoding). The CSRF token travels as an X-CSRFToken header via hx-headers rather than a form field, since there is no for a hidden input to ride along with — Django's CsrfViewMiddleware accepts either. {% endcomment %}
